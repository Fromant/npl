# NL_2026

Индивидуальная работа: 20 программ на 20 разных языках программирования. Пять тем, на каждую тему — по 4 программы. Специализированные библиотеки не используются — только стандартная библиотека каждого языка (потоки/tasks, сокеты, файловый ввод-вывод). Каждая программа — 50–100 строк, по ней записывается видео с построчным разбором кода.

## Порядок работы

Исходники каждой задачи лежат в папке своей темы: `<папка темы>/task_<номер>_<язык>/`. Внутри — один файл с программой и `README.md` с описанием и командой запуска.

## Языки

Clojure, D, Elixir, Erlang, F#, Groovy, Haskell, Julia, Kotlin, Lisp, Lua, Nim, ODIN, Perl, Prolog, Ruby, Rust, Scala, Scheme, Zig.

## Тема 1. Многопоточность

Папка: `1_threads/`

| № | Задача | Язык |
|---|--------|------|
| 1 | Сумма квадратов чисел на четырёх потоках | Julia |
| 2 | Очередь задач и три потока-воркера | Kotlin |
| 3 | Десять задач с задержкой и подсчёт одновременных | Elixir |
| 4 | Параллельная запись четырёх файлов | Rust |

1.1 **Julia.** Программа вычисляет сумму квадратов чисел от 1 до 10 000 000, распределяя вычисление между четырьмя потоками выполнения. Числовой диапазон делится на четыре равные части, части считаются одновременно. В консоль выводятся результат каждого потока, общая сумма и время работы.

1.2 **Kotlin.** Программа создаёт очередь из 20 заданий и распределяет их между тремя потоками-воркерами. Задание — «посчитать сумму цифр числа». Каждый воркер сообщает в консоль, какое задание взял и каков ответ. В конце выводится количество заданий, выполненных каждым воркером.

1.3 **Elixir.** Десять заданий выполняются одновременно, каждое со своей задержкой от 1 до 3 секунд. Для каждого задания печатаются момент начала и момент завершения. Программа определяет, сколько заданий выполнялось одновременно, и выводит максимальное значение и общее время работы.

1.4 **Rust.** Четыре потока одновременно записывают четыре разных текстовых файла. Каждый поток записывает в свой файл N строк вида «номер потока, номер строки». После завершения работы выводятся размеры файлов и общее количество записанных строк.

## Тема 2. Алгоритмические задачи

Папка: `2_algorithms/`

| № | Задача | Язык |
|---|--------|------|
| 1 | Сортировка слиянием (рекурсия) | Haskell |
| 2 | Бинарный поиск с печатью шагов (рекурсия) | Scheme |
| 3 | Обход графа в глубину (рекурсия) | Lisp |
| 4 | Поиск цикла в графе (рекурсия) | Prolog |

2.1 **Haskell.** Программа сортирует список чисел методом слияния: список делится пополам, половины сортируются рекурсивно, затем сливаются в один отсортированный список. Выводятся исходный список, отсортированный результат и количество выполненных слияний.

2.2 **Scheme.** Пользователь вводит число, программа ищет его в отсортированном массиве рекурсивным бинарным поиском. На каждом шаге в консоль выводится, какая середина массива проверяется и в какую половину продолжается поиск. Выводятся результат поиска и число выполненных шагов.

2.3 **Lisp.** В программе задан граф из шести вершин. Программа обходит граф в глубину из первой вершины и печатает порядок посещения вершин; уже посещённые вершины повторно не обходятся. Если граф изменить так, чтобы в нём появился цикл, обход всё равно должен завершиться.

2.4 **Prolog.** Для того же графа из шести вершин программа рекурсивно ищет замкнутый маршрут и выводит вершины найденного цикла. Программа должна работать и с графом без циклов, выводя сообщение о том, что цикл не найден.

## Тема 3. Ввод/вывод в консоль и файл

Папка: `3_io/`

| № | Задача | Язык |
|---|--------|------|
| 1 | Поиск подстроки в файле (grep) | Perl |
| 2 | Побайтовое копирование файла | Lua |
| 3 | Шифр Цезаря из файла в файл | D |
| 4 | Меню со списком покупок в файле | ODIN |

3.1 **Perl.** Пользователь вводит искомое слово. Программа читает входной текстовый файл построчно и записывает в выходной файл только те строки, где слово встретилось. В конце выводится количество найденных совпадений и количество прочитанных строк.

3.2 **Lua.** Программа копирует текстовый файл в другой файл. Копирование подтверждается сравнением: проверяются размеры исходного и полученного файлов, их содержимое, и выводится количество перенесённых байт. Обрабатывается и пустой файл.

3.3 **D.** Пользователь вводит величину сдвига от 1 до 25. Программа читает текстовый файл, сдвигает в нём каждую букву английского алфавита на заданное число и записывает результат в другой файл. Программа умеет и обратное преобразование: из зашифрованного файла получается исходный. Выводятся примеры прямого и обратного преобразования.

3.4 **ODIN.** Программа работает как консольное приложение со списком покупок: команды добавления позиции, показа списка, удаления позиции и выхода. Список хранится в текстовом файле между запусками: при старте файл читается, после каждого изменения сохраняется заново. Ошибочный ввод не приводит к аварийному завершению.

## Тема 4. Клиент-серверное взаимодействие

Папка: `4_client_server/`

| № | Задача | Язык |
|---|--------|------|
| 1 | Сетевой калькулятор | Erlang |
| 2 | Игра «угадай число» | Ruby |
| 3 | Сервер даты и времени | Groovy |
| 4 | Строка наоборот и счётчик клиентов | Nim |

Каждая программа состоит из серверной и клиентской части и запускается в одном из двух режимов, которые задаются при запуске. Обмен идёт по локальной сети.

4.1 **Erlang.** Сервер принимает соединение клиента и вычисляет присланное выражение вида `12+5`, отвечая результатом `17`. Поддерживаются четыре арифметические операции и команда завершения работы. Сервер ведёт счётчик подключившихся клиентов.

4.2 **Ruby.** Сервер загадывает число от 1 до 100 и отвечает на каждую попытку клиента сообщением «больше», «меньше» или «угадал», считает число попыток и после победы загадывает новое число. Одновременно могут работать несколько клиентов.

4.3 **Groovy.** Клиент запрашивает у сервера текущие дату и время одной командой, сервер отвечает строкой с датой и временем. Клиент может завершить сеанс командой выхода.

4.4 **Nim.** Клиент отправляет серверу строку текста, сервер возвращает её в обратном порядке. Сервер сообщает в консоль номер текущего подключения, чтобы было видно, что соединения обслуживаются независимо друг от друга.

## Тема 5. Конвертация данных из одного формата в другой

Папка: `5_convert/`

| № | Задача | Язык |
|---|--------|------|
| 1 | CSV в JSON | Clojure |
| 2 | Markdown в HTML | Scala |
| 3 | Римские цифры и арабские числа | F# |
| 4 | Base64 своими руками | Zig |

5.1 **Clojure.** Программа читает файл в формате CSV и записывает те же данные в формате JSON. Значения, содержащие запятые или кавычки, обрабатываются правильно, первая строка файла считается заголовком столбцов. Разбор форматов выполняется внутри программы, готовые библиотеки для CSV и JSON не используются.

5.2 **Scala.** Программа читает текст в формате Markdown и печатает эквивалентный HTML-документ. Поддерживается набор разметки: заголовки, маркированные списки, полужирный текст, курсив и код в кавычках. Обычный текст переносится в абзацы.

5.3 **F#.** Программа преобразует арабское число в римскую запись и обратно. Проверка выполняется на числах от 1 до 100 и на круглых значениях: результат обратного преобразования должен совпасть с исходным числом.

5.4 **Zig.** Программа преобразует текст в его запись в формате Base64 и обратно. Готовые функции кодирования не используются, преобразование выполняется вручную. После декодирования результат сверяется с исходным текстом, выводится и длина закодированной строки.
